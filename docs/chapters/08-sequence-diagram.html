CHAPTER 8 · WEEK 8

Sequence diagrams

A class diagram shows which classes exist. A sequence diagram shows them talking — which method calls which, in what order, for one activity. It is where the methods on your class diagram actually come from.

  • Read a sequence diagram: lifelines, activation bars, message types
  • Tell a synchronous call from an asynchronous one, and know when each is right
  • Use alt, opt, par and loop fragments
  • Derive the methods of your class diagram from a sequence diagram

8.1 — What it shows, and what it does not

A sequence diagram works at the method level: it shows calls between methods of different objects, in the order they happen. For logic inside a single method, use a flowchart — a sequence diagram is not the tool for that.

Read one top to bottom and you can write the program from it. That is the test of a good one.

Why bother, when you could just write the code? Because a sequence diagram shows the interface between objects. Once the class diagram and the sequence diagrams are detailed enough, a team can split up: whoever writes Account knows exactly which methods it owes and what they return, without reading anybody else's code.

Activation bars and who is busy

The object that sends a message is the message caller; the one that receives it is the message receiver. A bar appears on the receiver's lifeline for as long as it is working. Nested bars mean a call made during another call.

8.3 — Message types

Synchronous — filled arrowhead

The sender waits for the receiver to finish and return before doing anything else. Most calls are synchronous: this is an ordinary method call.

Asynchronous — open arrowhead

The sender does not wait. Used for long-running work: fire the request, carry on, and be told later by a callback or a message queue — e-commerce payment confirmation, for example.

Return — dashed arrow

Control and the result going back. For a synchronous call the return is implied, so drawing it is optional — leave it out when the diagram is getting crowded.

Reflexive — arrow to itself

An object calling its own method. Starts and ends on the same lifeline.

Constructor message

A call that creates an instance. The new lifeline starts at that point. Marked «create».

Destructor message

Destroys an instance. Rare in Python, where garbage collection handles it — you will see it in C++ or Java diagrams.

8.4 — Sequence fragments

A fragment is a labelled box around part of the diagram. The label in the top-left corner is the operator, and a condition in square brackets is a guard.

OperatorLogicShape
altif / else — two or more choicessplit by dashed lines into operands, each with its own guard. Exactly one runs.
optif, with no elseone block, one guard at the top left. Runs or does not.
looprepetitionone block with a guard; repeats until the guard is false. May carry minint / maxint.
parboth paths run in parallelsplit into operands that execute concurrently.

An alt fragment: login validation

You do not have to use fragments. There is no single fixed format. A repetition can be written as a message labelled “for each enrolment” instead of a loop box, and steps can be numbered. A good sequence diagram is one that creates understanding — if a fragment makes it harder to read, drop it.

8.7 — How to write one

  1. One activity, one diagram. Take a single use case from chapter 7.
  2. List the actors involved in that activity.
  3. List the classes involved — every lifeline must already exist on your class diagram.
  4. Walk the steps in order. At each one ask: which class must be told to do what? That question defines a method.
  5. Write those methods back into the class diagram. This is the whole point of the exercise — sequence diagrams are how the methods column gets filled in.
  6. Mark where objects are created. A Transaction comes into existence at a particular step; show it with a «create» message.
The two diagrams feed each other. The class diagram tells you which lifelines are legal; the sequence diagram tells you which methods those classes need. Draw both, alternate between them, and the design converges. Draw only one and you will be guessing.
