The four ideas everything else rests on

Every chapter in this course is an answer to one of these four. If you can say which problem each one solves, you can design; if you can only define them, you can only pass a vocabulary quiz.

capsule + make

Encapsulation

Keep data and the code that guards it in one place, and let nothing else touch the data directly. Solves: an object being put into a state that should be impossible.

 abs + trahere — draw away

Abstraction

Show the interface, hide the implementation; and pull what is common up into one place. Solves: having to understand all of a system in order to change part of it.

 is-a

Inheritance

A specific class takes everything a general class has, then adds its own specifics. Solves: the same rule copy-pasted into eight files, seven of which you forget to update.

 poly + morph — many forms

Polymorphism

One method name, many different bodies, chosen by the object itself at run time. Solves: the if/elif chain that grows every time the business adds a product.
Read this before chapter 1. OOP is not a rule book to obey. It is a set of trades: you accept more classes and more indirection, and in return you get fewer places to change when a requirement moves. Every chapter here states that trade explicitly, including the cases where the honest answer is “don't use OOP for this.”

How to get the most out of this site

  1. Read the “What breaks” box first. Each chapter opens with a program that works today and will hurt you later. If you cannot see the pain, the principle will feel like bureaucracy.
  2. Break the interactives on purpose. They are built to be abused — assign a negative GPA, delete half a list, add a seventh subclass. The failure messages are the lesson.
  3. Draw before you code. Every lab from week 3 onward is marked on the diagram first. Use the UML Studio until Check comes back all green, then write the class skeletons from it.
  4. Answer the “Choose correctly” questions. Knowing that composition exists is worth nothing in the exam; knowing when to pick it over inheritance is most of the marks.
