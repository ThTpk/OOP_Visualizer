CHAPTER 2 · WEEK 2

Objects, classes and instances

A class is a blueprint. An instance is a thing built from it, at its own address in memory. Getting this distinction physically clear is the difference between fluency and guessing for the rest of the course.

  • Write a class with a constructor, following Python naming conventions
  • Explain what self refers to, and why it must appear in every method signature
  • Predict what happens in memory when two instances are created from one class
  • Store one object inside another to model a relationship

2.1 — Class = blueprint, instance = thing

A class defines what every object of that kind will know (attributes) and be able to do (behaviours). It is a plan, not a building. Nothing exists in memory until you build from it.

    pass                # body goes here

In Python 3 you no longer write class Student(object): — every class inherits from object automatically. You will still see the old form in older code and in some textbooks.

2.2 — The constructor

You could create an empty instance and then assign every attribute by hand. With twelve attributes that is twelve lines, repeated at every creation site, and nothing forces you to set them all. The constructor solves this: it runs automatically whenever an instance is created.

__init__ — three things that look alike but are not
class Student:
    def __init__(self, student_id, name):
        self.student_id = student_id
        self.name = name
Why self must be there. self is the address of the instance currently being worked on. Without it Python would have no way to know whose student_id you mean. stu1.student_id and stu2.student_id are different memory, even though the name is identical.

The four mistakes everyone makes once

  • Forgot def — __init__(self, …) on its own is a call, not a definition.
  • Single underscores — _init_() is just an ordinary method. Python never calls it, so your attributes are never set and you get AttributeError on first use.
  • Forgot self in the parameters — def __init__(width, height): makes width receive the instance. Even a constructor with no parameters needs self.
  • Forgot self. on the left — name = name creates a local variable that is discarded the moment __init__ returns. The instance is left with nothing.

2.3 — Watch it happen in memory

Step through this. The point to internalise is the moment the second instance appears: a second, unrelated block of memory that happens to have the same field names.

Exam point. print(id(stu1.student_id)) and print(id(stu2.student_id)) give different numbers. Each instance holds its own data at its own address. Creating from the same class guarantees the same shape, never shared values.

2.4 — Dot notation: reading and changing state

Once an instance exists, you reach its data with dot notation: the instance name, a dot, then the attribute name. Writing to it changes the state of that one instance.

read, then write
stu1 = Student('001', 'John')

print(stu1.name)        # read  -> John
stu1.name = 'Johnny'    # write -> this instance only
print(stu1.name)        # read  -> Johnny

# inside the class, 'self' plays the role of the instance name
class Student:
    def rename(self, new_name):
        self.name = new_name
Hold this thought — it is chapter 3's entire subject. Nothing above stopped us writing stu1.name = 42, or stu1.gpa = -5. Direct attribute access from outside the class breaks information hiding. Next chapter we take that ability away, on purpose.

2.5 — One object inside another

Real systems are objects that hold other objects. A Subject needs to know which students enrolled. It stores the whole instance, not a copy of the name — that is what keeps one fact in one place.

✗ storing a copy of the data
class Subject:
    def __init__(self, subject_id, subject_name):
        self.subject_id = subject_id
        self.subject_name = subject_name
        self.student_names = []

oop = Subject('CS101', 'OOP')
oop.student_names.append('John')

# John changes his legal name…
stu1.name = 'Jonathan'
print(oop.student_names)   # ['John'] — stale forever
The name now exists in two places and they have drifted apart. This is the parallel-list bug from chapter 1, wearing a class.
✓ storing the instance
class Subject:
    def __init__(self, subject_id, subject_name):
        self.subject_id = subject_id
        self.subject_name = subject_name
        self.student_list = []

oop = Subject('CS101', 'OOP')
oop.student_list.append(stu1)      # the whole object

stu1.name = 'Jonathan'
print(oop.student_list[0].name)    # Jonathan — always current
One Student object, referenced from wherever it is needed. Change it once and every holder sees the change.

This is also why lab briefs say “do not duplicate data” and “data stored in a non-basic class must be an instance of the basic class only.” It is not style — it is the bug above.

A class can reference its own kind

A student can have a mentor (พี่รหัส), who is also a student. A person has friends, who are people. In a class diagram this is a self-association (chapter 4).

self-association
class Student:
    def __init__(self, student_id, name, year):
        self.student_id = student_id
        self.name = name
        self.year = year
        self.mentor = None          # another Student, or None

a = Student('a', 'Ann', 1)
b = Student('b', 'Ben', 2)
a.mentor = b                        # Ben mentors Ann

def mentor_chain(student):
    while student.mentor is not None:
        print(student.name, '→', student.mentor.name)
        student = student.mentor
